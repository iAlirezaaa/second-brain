# Contributing — Second Brain OS

Thanks for considering a contribution. This repo is a plain-markdown brain a human curates and
AI agents maintain, wrapped in a toolchain that enforces its own rules — the standing discipline
is **every rule is a script, not a suggestion**. Contributions that follow that discipline are
welcome; contributions that add a rule with no gate behind it will be asked to add the gate.

## Setup

```bash
git clone https://github.com/iAlirezaaa/second-brain-os.git
cd second-brain-os
python -m unittest discover -s tests   # the whole suite
python scripts/health.py               # every integrity gate, in one run
```

Python ≥ 3.9 (the floor CI proves on ubuntu-24.04 + windows-latest), **no pip dependencies** —
engine scripts stay stdlib-only, and a PR that adds one needs a decision note in
`02_WIKI/decisions/` before code. Nothing here needs Obsidian: any editor reads the same files.

## The protocol, in the order it actually works

1. **A gap becomes an issue first.** The roadmap's own rule: "each gap becomes an issue first,
   then a test-first fix." Prose that describes a defect without an issue number is how defects
   survive.
2. **Write the test before the behaviour.** Every phase in `ROADMAP.md` cites the test that
   holds it. If you add a script or a skill, the same commit carries its unittest coverage.
3. **A governed record goes through the door, not the editor.** Registry records
   (`11_CONTROL/**`) are created by `15_SYSTEM/scripts/hades.py plan …` then
   `apply --plan … --approve` by the human. Hand-written records fail `doctor`, and an agent
   approving its own plan is refused by design.
4. **Machine output never touches the human shelves.** Agent artifacts land on the quarantine
   shelf `14_CANDIDATES/` (loop reports, candidates, probes) and reach the numbered human zones
   only through `scripts/promote.py`, which requires the evidence a promotion promises.
5. **Numbers in documents are measurements.** `README.md`, `HANDOFF.md` and
   `00_START_HERE/START.md` carry blocks generated by `scripts/doc_report.py`. If you add a
   test, a gate or a zone, run `python scripts/doc_report.py --write` in the same commit —
   `health.py` refuses a document whose numbers no longer describe the folder it sits in.
6. **The version is derived, not typed.** `python scripts/version.py --show` prints the next
   number from the commit subjects since the last tag (`feat!`/`BREAKING CHANGE` → major,
   `feat` → minor, `fix`/`perf` → patch, docs/tests/chore → `NO_BUMP`). `--check` refuses when
   `VERSION`, `pyproject.toml`, the README title and badge, and `CHANGELOG.md` disagree.
   Tagging and pushing stay human acts — the gate prints the commands, it never runs them.
7. **Design work is reviewed by a stranger.** Anything that changes behaviour gets a
   zero-context review before implementation (see `skills/goldfish-review/SKILL.md` and
   `scripts/goldfish_check.py`): the drafter writes the spec, fresh reviewers judge the document
   and its cited files without the conversation. A review done in the drafter's own context is
   not a goldfish review, and the tooling stops rather than pretending.

## The gates `health.py` runs

The source of truth is `scripts/health.py:GATES`. The following table must contain
exactly the same gate names; `tests/test_backlog_governance.py` checks drift.

| gate | what it refuses |
| --- | --- |
| `scripts/link_check.py` | links resolving to missing destinations |
| `scripts/link_check.py --readout` | ambiguous link graph edges |
| `scripts/frontmatter_check.py` | invalid notes and registry metadata |
| `scripts/plane_check.py` | declared memory planes missing stores or readers |
| `scripts/candidate_check.py` | proposals with missing or inconsistent evidence |
| `scripts/memory.py --check` | invalid lesson ledger or stale generated memory |
| `scripts/sync_hosts.py --check` | host instructions drifting from AGENTS.md |
| `scripts/doc_report.py --check` | stale or unmeasurable document statistics |
| `scripts/vector_check.py` | unsupported embedding activation |
| `scripts/issues.py --check` | missing or inconsistent issue ledger |
| `scripts/version.py --check` | incompatible version tags and metadata |
| `scripts/ci_floor.py` | CI Python versions below the supported floor |
| `scripts/goldfish_check.py` | invalid independent review artifacts |
| `scripts/schema_stamp.py --check` | stale generated JSON schemas |
| `scripts/roadmap_check.py --check` | missing roadmap evidence |
| `scripts/vault_check.py` | unjustified backup claims |

A new gate must be implemented, registered, tested and documented together;
removing a failing gate is not a repair.

## What a good PR looks like

- title follows Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`) — the version
  bump is read from it, so a vague subject is a lost release note;
- small and focused: one idea, one commit series;
- `python -m unittest discover -s tests` and `python scripts/health.py` both green, with the
  regenerated numbers included;
- `ROADMAP.md` ticked where the phase row promises it, and `CHANGELOG.md` under
  `## [Unreleased]` stating what a reader can now do that they could not before;
- claims carry the command that proves them. "Recall improved" is refused without a case set,
  a limit, a corpus hash and a before/after report (`scripts/probe.py`, `--save`/`--recover`).

## Bilingual note

User-facing docs are English + Persian (فارسی). Changing either half is enough in a PR;
maintainers keep them in sync. `AGENTS.md` is the agent-facing canon and is projected into the
host doors by `scripts/sync_hosts.py` — edit the canon, never a projection.
