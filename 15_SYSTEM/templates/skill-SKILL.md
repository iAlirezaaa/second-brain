# قالب: اسکیل (11_CONTROL/skills)

اسکیل چیزی است که ایجنت **با آن کار می‌کند**، نه چیزی که درباره‌اش می‌خوانی. پس
هر خط باید یا شرط ورود باشد یا دستور اجرایی. توضیح ادبی حذف می‌شود.

نام پوشه و `name:` باید ASCII کوچک با خط تیره باشد؛ فارسی فقط در بدنه می‌نشیند.
دلیل: هارنس‌ها از `name` برای پیدا کردن اسکیل استفاده می‌کنند و slug فارسی را
نمی‌شناسند.

---

```markdown
---
name: skill-name-in-ascii-kebab
description: یک جمله: چه کاری، و کِی استفاده شود. ایجنت فقط این را می‌خواند و تصمیم می‌گیرد.
---

## Trigger
چه درخواست یا چه وضعیتی این اسکیل را فعال می‌کند.

## Prerequisites
چه چیزی باید قبلاً موجود باشد. اگر نیست، اسکیل باید بایستد نه اینکه حدس بزند.

## Procedure
1. قدم اول، با دستور دقیق یا نام فایل.
2. گیت میانی: چه چیزی بررسی می‌شود و اگر رد شد چه اتفاقی می‌افتد.
3. ...

## Boundaries
کارهایی که اسکیل هرگز نمی‌کند. این بخش اجباری است؛ بدون آن، اسکیل یک مجوز بی‌نهایت است.

## Output template
شکل خروجی که کاربر تحویل می‌گیرد.
```

## آزمون
- یک ورودی درست و یک ورودی ناقص بنویس؛ اسکیل باید در دومی رد کند.
- اگر اسکیل عدد یا مشخصه‌ای می‌نویسد، منبعش را ذکر کند یا جای خالی بگذارد — نه نمونه‌ساخته.
- `py -3.10 15_SYSTEM/scripts/hades.py sync --harness HARNESS-ID` بعد از تأیید اسکیل.
