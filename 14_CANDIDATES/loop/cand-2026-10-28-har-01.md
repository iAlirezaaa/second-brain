# cand-2026-10-28-har-01

**Invariant.** the config already named the gap: `"status": "v3 skeleton, no live orchestration"`,
`vector_search: false`, an empty `15_SYSTEM/integrations/`, an empty `11_CONTROL/mcp/`. The
registry can *describe* agents, harnesses, MCP servers and workflows, but nothing lets a
harness actually call the brain, and nothing records what an agent run did.

Reverse-engineered from SuperAGI (repo + its SQLAlchemy core: `Agent`, `AgentConfiguration`,
`AgentExecution` with CREATED/RUNNING/PAUSED/COMPLETED/TERMINATED, execution steps and feeds,
toolkits, knowledge/vector storage, schedules, marketplace, telemetry):

| SuperAGI | verdict here |
|---|---|
| FastAPI + Postgres + Celery/Redis + Next.js GUI | refuse — five machines to patch; the harness already speaks MCP |
| Agent → AgentExecution → Steps → Feed | adopt as `12_RUNTIME/agent_runs/` (`runs.py`): run.json + steps.jsonl, disposable |
| Toolkits / tools | already modeled: `skill`/`command`/`mcp` records + `approved_for_harness_ids` |
| Vector memory (Pinecone/Chroma) | keep behind the `vector_search` flag; today FTS5 keyword search is the honest floor, embeddings are the phase-2 upgrade behind the same interface |
| Knowledge indexing | phase 2, via the same search seam |
| Schedules / cron | already modeled (`loop` kind + nightly workflow) |
| Marketplace | refuse — the shelf + probes are the internal exchange; no network |
| Telemetry | already here in its strongest form: measured numbers in the docs |

What phase 1 implements:

- `15_SYSTEM/scripts/mcp_server.py` — the harness door: `initialize`, `tools/list`,
  `tools/call`, `resources/list`, `resources/read`, `ping`, batched messages, JSON-RPC
  errors; read tools (`vault_search`, `memory_recall`, `registry_list`, `registry_show`,
  `doctor_status`) and one write tool, `candidate_propose`, which writes where an agent's
  writes belong — a registered row on the quarantine shelf.
- `15_SYSTEM/scripts/runs.py` — the run ledger: `start` (refuses an unregistered actor),
  `step` (append-only feed), `finish`, `list`, `show`.
- `hades.py check_entrypoints` learns the MCP law: a record whose `endpoint_or_command`
  points at a `.py` file must point at a file that exists.

To decide it: set `probe:` to `15_SYSTEM/scripts/test_hades.py`, flip the verdict to what a
real run supports, then `python scripts/probe.py --candidate 14_CANDIDATES/loop/cand-2026-10-28-har-01.md`,
`python scripts/candidate_check.py --file 14_CANDIDATES/loop/cand-2026-10-28-har-01.md`,
and write the disposition as the human decides.
