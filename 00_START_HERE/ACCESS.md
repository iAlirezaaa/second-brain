# دسترسی، رازها و مرز Git

## دو صفحه، دو سطح انتظار

صفحه انسان (۰۰ تا ۱۰) برای خوانده‌شدن است؛ صفحه ماشین (۱۱ به بعد) برای سوختن ماشین. چیزی که تو لازم نیست بدانی، **حالت و لاگ** است نه دانش. دانشی که فقط در حالت ماشین زنده باشد، در این سیستم «هنوز دانش نشده» حساب می‌شود و باید promote شود.

## پیش‌فرض‌ها (منبع حقیقت: `15_SYSTEM/config/system.json`)

- **خواندن مجاز:** ۰۰ تا ۱۰ + `11_CONTROL`
- **خواندن ممنوع:** `12_RUNTIME`، `13_LAB`، `14_CANDIDATES`، `15_SYSTEM/generated`، `15_SYSTEM/backups`، `09_OPERATIONS/clients_metadata_only`
- **نوشتن:** فقط به مسیری که نوع رکورد تعیین می‌کند؛ اسکریپت‌ها هیچ‌جا بیرون از رجیستری نمی‌نویسند
- **classification:** `public` / `internal` / `confidential` / `restricted`؛ پیش‌فرض `internal`

دیدنِ پوشه، دسترسی نیست. تا `filesystem_acl_enforcement` روشن نشود (و در این بسته روشن نیست)، اینها **قرارداد**‌اند که ایجنت مؤدب رعایت می‌کند، نه دیواری که سیستم تو را مجبورش کند. `doctor` این تفاوت را در خروجی‌اش تکرار می‌کند تا کسی فریب نقشه‌ی زیبا را نخورد.

## رازها

- هیچ کلید، رمز، کوکی، توکن یا فایل session داخل Vault نه. فقط `secret_ref` با اشاره به مدیر رمز.
- هر فایل متنی که `export` یا `publish` می‌شود از اسکنر الگو + آنتروپی رد می‌شود؛ اگر یک فایل علامت بخورد، کل خروج متوقف می‌شود (نه حذف آن فایل و ادامه).
- `doctor` همین اسکنر را روی کل Vault اجرا می‌کند، چه قصد انتشار داشته باشی چه نه.

## مرز Git: مخزن خصوصی OS + مخزن جدا برای هر پروژه

- **مخزن OS:** ۰۰ تا ۱۰، `11_CONTROL` و `15_SYSTEM` (به‌جز `generated/` و `backups/`).
- **خارج از مخزن:** `12_RUNTIME`، `13_LAB`، `14_CANDIDATES`، `15_SYSTEM/generated`، هر نوع credential، و فایل حجیم.
- **کد هر پروژه:** مخزن خودش، بیرون از Vault. Vault فقط مانیفست، مستندات و آدرس مخزن را نگه می‌دارد.
- **مخزن تودرتو:** اگر داخل Vault یک `.git` تازه سبز شود، `doctor` خطا می‌دهد. دو تاریخچه برای یک چیز، یعنی کدام‌یکی واقعی است؟
- **انتشار:** هیچ‌چیز خودکار بیرون نمی‌رود. مسیر: `export` (ممیزی، بدون نوشتن بیرون) → بازبینی تو → `publish --approve` (فقط repo خصوصی تازه) → و بعد **خواندن دوباره‌ی وضعیت مخزن از GitHub** تا «خصوصی» بودن ادعا نماند. اگر repo از قبل وجود داشته باشد، رد می‌شود.

## بکاپ (چیزی که ساختار تضمین نمی‌کند)

GitHub بکاپ نیست، Sync بکاپ نیست. سه نسخه لازم است: SSD سالم، دیسک مستقل، و مقصد رمزنگاری‌شده خارج از محل. این بسته فقط **مانیفست بکاپ** و مسیرهای مرجع را نگه می‌دارد؛ ابزار (Restic یا هرچیز دیگر) و زمان‌بندی‌اش بیرون از اینجا نصب و آزمون می‌شود. چیزی که restore‌اش آزمایش نشده، بکاپ نیست.
