# معرفی فارسی Second Brain OS

> **مغزی محلی برای به‌خاطرسپردن، پیدا‌کردن، ارتباط‌دادن و تبدیل دانش به کار قابل‌سنجش.**

Second Brain OS پروژه‌ای متن‌باز و مستقل از سرویس‌های پولی است که حافظه شخصی، منابع، پروژه‌ها، وظایف، مهارت‌ها و ایجنت‌های هوش مصنوعی را به یک جریان کاری مشترک متصل می‌کند. هدف آن فقط پوشه‌بندی و نگهداری یادداشت‌ها نیست؛ هدف این است که اطلاعات قدیمی و جدید را به‌درستی بازیابی کند، میان آن‌ها ارتباط‌های غیرمنتظره پیدا کند و در اجرای کارها، نتیجه‌ای قابل‌بررسی ارائه دهد.

**نام عمومی:** Second Brain OS  
**نام موتور:** HADES  
**فلسفه:** محلی و قابل‌انتقال، سبک روی دستگاه ضعیف، توسعه‌پذیر روی GPU، با کنترل نهایی انسان.

## امکاناتی که واقعاً وجود دارند

- نگهداری دانش و پروژه‌ها در فایل‌های قابل‌خواندن و ساختار شماره‌گذاری‌شده.
- جست‌وجوی مبتنی بر متن، برخی مخازن SQLite و ذخیره درس‌های ثبت‌شده.
- اتصال ایجنت‌ها از طریق MCP و رجیستری ابزارها.
- CLI جدید برای ساخت جلسه، لیست کار، اضافه‌کردن تسک، ثبت شواهد و هندآف اجباری.
- نسخه اولیه ADHD برای یافتن ارتباط‌های واژگانی بین حوزه‌های متفاوت؛ این ارتباط‌ها فرضیه هستند، نه حقیقت تأییدشده.
- Twin World اولیه برای شبیه‌سازی تغییر وضعیت تسک و نمایش Diff تغییر فایل در حافظه؛ هنوز Sandbox واقعی اجرای کد نیست.
- اتصال اختیاری Laya برای پیشنهاد تصمیم‌های ساختاریافته؛ مدل و وزن‌ها به‌صورت پیش‌فرض نصب نشده‌اند.

## امکاناتی که هنوز باید تکمیل شوند

جست‌وجوی ترکیبی و گراف دانش زمان‌مند، احراز هویت مستقل ایجنت‌ها، اجرای موازی و پایدار چندایجنتی، Sandbox ایزوله، ترکیب و ارتقای تأییدشده Skills، بکاپ عملیاتی کاربر و رابط‌های موبایل/مرورگر به آزمایش و توسعه بیشتری نیاز دارند. سبزشدن CI به معنای کامل‌بودن این قابلیت‌ها نیست.

## شروع کار

از ریشه ریپو:

\`\`\`bash
python scripts/health.py
python -m unittest discover -s tests
python scripts/brain.py skills --query "research"
python scripts/brain.py start --goal "Organize my next research task"
\`\`\`

CLI شناسه‌ای با پیشوند \`SES-\` می‌سازد که می‌توانید با دستورهای \`status\`، \`add\`، \`done\`، \`trace\` و \`handoff\` مدیریت کنید. بدون بازبینی Skills و برنامه، مسیر اجرای سخت‌گیرانه اجازه فراخوانی ابزار را نمی‌دهد. پایان موفق کار نیازمند شواهد، هندآف و تأیید انسان است.

برای جزئیات اجرایی انگلیسی [راهنمای CLI](CLI_VNEXT.md)، برای هدف جامع [چشم‌انداز محصول](PRODUCT_VNEXT.md) و برای نقش‌ها [تیم ایجنت‌ها](AGENT_TEAM_VNEXT.md) را بخوانید.

## قانون‌های اساسی

اطلاعات خصوصی در Git عمومی قرار نمی‌گیرند. ایجنت نمی‌تواند با ادعای خودش مجوز جدید بسازد، نتیجه کارش را مستقلاً تأیید کند یا Skill جدید را بدون بررسی به مجموعه اصلی ارتقا دهد. تغییر معماری ابتدا باید در محیط جدا شبیه‌سازی و تست شود و در صورت افت عملکرد، قابل بازگشت باشد.
